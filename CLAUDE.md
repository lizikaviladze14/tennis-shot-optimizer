# Tennis Shot Optimizer

Vue 3 + TypeScript + Vite + Vitest. A Monte Carlo model recommends where to aim a
tennis shot. All model parameters are illustrative, not fitted to data.

## Folders

- src/math/: the model. Pure functions, plain data in and out, no Vue, no DOM.
- src/analysis/: pure code built on the model, no Vue, no DOM: the shared
  scenario builder (buildScenario, used by App.vue, the script and the dialog)
  and the sensitivity analysis.
- src/animation/: animation geometry (imports from src/math/, never the reverse).
- src/utils/: UI wording and formatting.
- src/workers/: web workers; they import from src/math/ and src/analysis/ only.
- scripts/: Node scripts, run with `npx vite-node scripts/<name>.ts`.
- docs/model-notes.md: every modeling decision and simplification.
- docs/sensitivity.md: the sensitivity analysis, hand-written; never overwrite.
  docs/sensitivity-results.md is generated by scripts/sensitivity.ts.

## Rules

- Never put Vue refs or reactive objects into postMessage: send plain copies.
- Functions can't be sent to workers; build them inside the worker.
- Tests live next to each folder in `__tests__/`. Existing test expectations must
  not change unless the task says so. Run:
  `npm run test:unit -- src/math/__tests__ src/utils/__tests__ src/animation/__tests__ src/analysis/__tests__ --run`
- Simple vs Detailed: modes stay out of src/math/; App.vue (via buildScenario in
  src/analysis/) decides what to pass in.
- Keep changes scoped to the task. Ask before restructuring unrelated code.
